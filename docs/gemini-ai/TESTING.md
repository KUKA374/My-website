# Gemini AI — іске қосу және тексеру

## 1. Кілтсіз жергілікті сынақ

Node.js **24.19.x** және Chromium/Playwright браузерлік тестке қажет.
Қолданушыға demo-ны көру үшін тек Node.js жеткілікті; fixture режимі нақты API шақырмайды.

```sh
cd /path/to/My-website
npm ci --prefix server/ai-lessons --omit=optional --ignore-scripts
npm --prefix server/ai-lessons run demo
```

**http://127.0.0.1:8787/admin.html** ашыңыз →
**«AI арқылы сабақ дайындау · тест»** → **«Жеке сабақ жобасын дайындау»**.

ҚМЖ бөлімін, 12 слайдты, тапсырмалардың шешімдерін және статистиканы қарап шығыңыз.
Бетті қайта ашып, сақталған жобаны таңдаңыз. Fixture генерациясы Gemini сұрауы немесе
токен қолдану ретінде көрсетілмейді. Бұл — нақты Firebase админ сессиясын тексеру емес.

Demo жеке SQLite файлдарын ОС уақытша қалтасындағы `iustaz-ai-demo` каталогында сақтайды.
Басқа сабақтар мен қолданыстағы браузер кітапханасын өшірмейді.
Сұрау лимиті аяқталса, UTC тәулігінің ауысуын күтіңіз; demo деректерін жою міндетті емес.
Серверді тоқтату: Ctrl+C. Demo-ны интернетке немесе production-ға шығармаңыз.

## 2. Нақты Gemini тестіне не дайындау керек

Осы ортада Gemini secret binding/ADC жоқ, ал `generativelanguage.googleapis.com`
желілік allowlist-те жоқ. Нақты сұрау жіберілген жоқ; API кілті сұралмайды.

Сервер әкімшісі мына инфрақұрылымды дайындайды:

1. Node 24.19.x сервер, админ UI мен `/api/ai-lessons/*` үшін бір origin. Production үшін HTTPS
   және reverse proxy қажет. GitHub Pages бұл Node API-ді орындамайды; тек батырма қосу жеткіліксіз.
2. Сервер secret manager-інен **`GEMINI_API_KEY`** айнымалысын енгізу. Оны браузерге,
   Git-ке немесе чатқа бермеңіз. Қолжетімді JSON-schema режимін қолдайтын нақты модельді
   **`GEMINI_MODEL`** арқылы таңдаңыз; код модельдің бар екенін ойдан болжамайды.
3. Қолданыстағы/арнайы тест Firebase project үшін **`FIREBASE_PROJECT_ID`** және ADC/workload identity.
   Құпия service-account JSON-ды репозиторийге салмаңыз. Token audience осы project-ке сәйкес болуы тиіс.
4. Сервер identity-іне рөлді оқу үшін `datastore.entities.get`, revocation тексеру үшін
   `firebaseauth.users.get` рұқсаттары қажет. Бұл кодқа Firestore write рұқсаты қажет емес.
   Қауіпсіздік әкімшісі project саясаттарына сай минималды IAM рөлін таңдауы тиіс.
5. Браузердің Firebase конфигурациясы сол project-ке сәйкес болуы керек. Бұл өзгерісте
   production `firebase-config.js` ауыстырылмайды; жеке staging конфигурациясын бөлек дайындаңыз.
6. **`AI_DATA_DIR`** — статикалық сайттан тыс, серверге ғана қолжетімді, тұрақты дискідегі абсолютті
   қалта. Каталог 0700, SQLite 0600. Бұл нұсқа бір серверлі тестке арналған. Тұрақты volume-сыз
   serverless instance-ке немесе ортақ SQLite файлсыз бірнеше instance-ке deploy жасамаңыз.
7. Шығыс желі: `generativelanguage.googleapis.com`, `firestore.googleapis.com`,
   `identitytoolkit.googleapis.com`, `www.googleapis.com`, `oauth2.googleapis.com`;
   workload identity қажет болса, соған сәйкес STS/metadata endpoint-тері. Басқарылатын ортада
   берілген proxy/CA параметрлерін сақтаңыз; Node fetch үшін `NODE_USE_ENV_PROXY=1` қолданыңыз.
8. Google AI жобасында API қолжетімділігі, модель квотасы және шығын лимиттері. Қате сұраудың
   токені белгісіз қалуы мүмкін; Google usage/billing панелімен салыстырыңыз.

`server/ai-lessons/.env.example` тек айнымалы атауларын көрсетеді, нақты кілт сақтамайды.
Файл автоматты оқылмайды: secret manager айнымалыларды сервер процесіне енгізеді.
Нақты мәндер қауіпсіз бапталғаннан кейін:

```sh
# GEMINI_API_KEY және ADC credentials secret manager/сервер ортасында бұрыннан берілуі тиіс.
# Төмендегі экспорттарда құпия мән жоқ.
export AI_GENERATION_MODE=gemini
export AI_DATA_DIR=/absolute/private/path/iustaz-ai
export AI_PUBLIC_ORIGIN=http://127.0.0.1:8787
# FIREBASE_PROJECT_ID және GEMINI_MODEL серверде нақты қолжетімді мәндерге бапталады.
node server/ai-lessons/index.cjs
```

Модель не кілт жоқ болса, Gemini режимі іске қосылмайды. `off` — әдепкі режим;
`fixture` нақты админмен ақылы емес сценарийді тексеруге арналған. Нақты entry point
emulator token қабылдамайды; emulator орнына оқшау `demo.cjs` пайдаланылады.

## 3. Бір нақты сабақпен smoke test

- Расталған admin/super_admin аккаунтымен кіріңіз. Браузер sessionStorage-ындағы жалған рөл жеткіліксіз.
- Батырманы ашып, нақты №3 КТП атауы мен мақсатын тексеріңіз.
- Бір рет генерация бастаңыз. Екінші басу сұрауды қайталамауы керек.
- Тек осы админге арналған жоба, дәл 45 минут, 12 слайд, барлық бөлім және `draft` күйі сақталуы тиіс.
- Gemini токен статистикасын Google usage дерегімен салыстырыңыз. Бағасы бұл интерфейсте есептелмейді.
- Түбірлерді бастапқы теңдеуге қойып, барлық математикалық тұжырымды админ өзі тексереді.
  Schema-дан өту математикалық дұрыстықтың дәлелі емес. Жариялау әрекеті жоқ.
- Мұғаліммен және басқа админ UID-імен осы draft ID-ін сұрап, 403/404 шекарасын тексеріңіз.
- Құпияны, ID token-ді және provider error body-ді логқа не скриншотқа түсірмеңіз.

Бұл нақты smoke test осы жұмыста **орындалмаған**, себебі жоғарыдағы инфрақұрылым жоқ.
Production Firebase деректері өзгертілген жоқ.

## 4. Автоматтандырылған тексеру

```sh
python tests/run-ai-lesson-qa.py
npm audit --prefix server/ai-lessons --omit=dev --omit=optional
```

Бұл командаларда Gemini және production Firebase шақырылмайды. HTTP/provider/auth тесттері
mock нұсқаларды, браузерлік тесттер loopback demo-ны қолданады. Playwright пен Chromium
болмаса, оларды әзірлеу ортасына бөлек орнату қажет.

Firebase Admin SDK — 14.5.0. Қолданылмайтын optional Firestore/Storage SDK-лары орнатылмайды:
рөл тек REST арқылы оқылады. Орнатылған runtime тәуелділіктерінің аудиті — **0 осалдық**.
Lockfile upstream optional пакеттердің метадеректерін де сақтайды; `--include=optional`
қолданылса, бұл экспериментте пайдаланылмайтын тізбекте 6 moderate ескерту шығады.
Оларды production орнатылымына қоспаңыз; optional SDK қажет болса, бөлек жаңартып тексеріңіз.

`node:sqlite` Node 24-та эксперименттік ескерту беруі мүмкін. Бұл сынақ прототипі үшін
қолданылады; көп instance/production сақтау архитектурасы мен backup бөлек қаралады.
Нақты Firebase токені, нақты Google желісі, модель квотасы және AI мәтіндерінің математикалық
дұрыстығы mock тест нәтижесімен расталмайды.
